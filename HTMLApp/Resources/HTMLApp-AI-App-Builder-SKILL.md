# HTMLApp — AI App Building Skill

HTMLApp is an iOS shell for creating, importing, editing, saving and launching small apps made with HTML, CSS and JavaScript. It supports iOS 16+; Apple Intelligence on-device features require compatible iOS 26+ devices. The user can take a self-contained HTML file generated by a subscription AI assistant (no API key required for the file creation) and import it using HTMLApp's Files interface or iOS Open In menu.

## Your job

When asked to make a new HTMLApp app, produce an **actual, working, complete HTML5 file** in a code artifact the user can save with the `.html` extension. Do not merely describe an app. Make the visuals distinctive for its purpose, with functional buttons, inputs, persistence, empty states and errors. Prefer a single standalone document containing inline CSS and JavaScript.

A subscription AI model working in its own chat creates or edits this file; HTMLApp itself does not automatically connect to that subscription or run the assistant's cloud account. To revise an app, ask for its existing HTML, edit it, and return the complete revised file unless the user requests patches.

## Host environment

HTMLApp runs saved HTML in WKWebView and may expose `window.HTMLAppNative` and `window.HTMLApp`. These are **not browser standards**; they are absent in Safari, normal websites and some previews. Check existence and availability, ask users before sensitive operations, and give an honest fallback. Supported capabilities differ by OS, device, permissions and signing/entitlements. Never invent methods: request the installed HTMLApp API catalog or inspect `HTMLAppNative.capabilities.list()` when available.

Examples of potential host integrations on supported builds include file and photo picking, document scanning, local app storage, structured SQLite data, widgets, notifications, location, reverse geocoding, mapped road speed-limit lookup, QR scanning, speech, Bluetooth LE, Core Image, PDF text inspection, maps, NFC, HealthKit, drawing, haptics, gamepad input and AI. Each needs its actual documented method and may require explicit per-saved-app permission. GPS provides coordinates and speed, NOT a street address or a posted speed limit. HealthKit/NFC/Apple Intelligence may not work under all signing configurations.

Use feature detection:
```js
const native = window.HTMLAppNative;
const hasFilePicker = !!native?.files?.pick;
if (!hasFilePicker) showMessage('Open this app inside HTMLApp to pick files.');
```
Do not silently access contacts, health, location, camera or microphone, and never assume a permission was granted. Catch rejections, handle cancellation, and offer retry.

## Offline vs online — critical

A self-contained HTML file **does not contain a server**. It can work offline for local UI, calculators, notes and some native device features. A cloud AI API, website backend, GitHub Actions build service, Discord webhook, Theos compiler or other remote process still needs a working network connection and an independently deployed server. Do not claim to compile iOS tweaks, generate binaries, deliver pushes or run a server using HTML/CSS/JS alone.

When code uses a relative endpoint such as `fetch('/api/build')`, this works only when the HTML is served from the website hosting that API. Imported into HTMLApp with a `file:` or sandbox origin, `/api/build` points at the local app origin rather than the original cloud server. **Ask the user for the exact hosted backend base URL. Never guess it or hardcode unverified endpoints.** Preferred choices:
1. Open the existing hosted website as a website app in HTMLApp, preserving same-origin API routes; or
2. With explicit user-supplied HTTPS endpoint and allowed CORS/permissions, use an absolute URL to call the backend.

For remote integrations show a setup screen and a clear online/offline status. Do not download, cache, or rewrite API routes as if they were static assets. Avoid caching secrets. Never expose tokens in a publicly shared HTML file.

## Quality requirements

- Semantic, accessible HTML. Responsive on compact iPhone and iPad, respecting safe areas. Fixed page scale (no pinch/double-tap zoom): 16px minimum input text, accessible scalable typography, and actual responsive reflow.
- No document-level horizontal scrolling at ANY supported viewport or orientation. Only deliberately horizontal components (carousels, chip strips, graph timelines, wide table wrappers) may scroll sideways; mark them data-htmlapp-horizontal-scroll="true". Fix oversized elements rather than simply clipping them; use min-width:0, fluid media and wrap long strings.
- Actual working interactions: no dead buttons, fabricated server results, or fake completion.
- Persistent data only when needed; use localStorage/IndexedDB or real documented HTMLApp storage.
- Input validation, error recovery, cancellation, bounded requests and reasonable upload sizes.
- Distinctive visual design (purposeful typography, shapes, hierarchy, colors and motion); respect reduced motion.
- Avoid CDN dependencies for apps requested to work offline.
- Verify browser JavaScript syntax; test empty and populated states.
- Do not present speculative iOS APIs as supported without capability checks.

## How to deliver

Return the full HTML file with a clear filename, brief instructions for saving it and importing it into HTMLApp, a note identifying any online services, permissions or external server dependencies, and any hardware-only tests the user must perform. For edits, retain the user's data keys and functionality and explain necessary migrations.

## Native bridge discovery and safe cancellation

Recent HTMLApp runtimes expose `HTMLAppNative.protocolVersion`, `await HTMLAppNative.capabilities.has(method)`, `await HTMLAppNative.capabilities.describe(method)`, and `HTMLAppNative.permissions.status(name)` / `.request(name)`. Do not equate host permission with iOS system authorization. `HTMLAppNative.call(method, args, {signal})` can abandon a pending promise on AbortSignal; only currently cancellable native operations such as supported AI requests stop their underlying native task. Do not claim arbitrary operations are cancellable. Continue feature-detecting older runtimes.

## Native UI controls

Supported recent runtimes can use `HTMLAppNative.ui.alert({title,message,actions})`, `.menu(...)`, and `.datePicker({title,mode,value})` for real UIKit dialogs/pickers. Show them only in response to user intent; excessive modal requests are rate-limited. `HTMLAppNative.events.on(name, handler)` subscribes to existing `htmlapp:*` native events (and returns an unsubscribe function). Do not invent unimplemented native UI primitives.

## Runtime helpers for real applications

Current HTMLApp releases may expose `HTMLAppData.collection(name)` (`put/get/remove/query/search/count`), `HTMLAppData.kv` (native portable appStorage), and `HTMLAppData.migrate(name, version, migrations)` for versioned, idempotent schema changes. `HTMLAppRuntime.runOperation(key, async ({signal}) => work, onStatus)` consolidates per-operation loading/error/cancel behavior; `cancelOperation(key)` and `onActive/onInactive/onBackground/onResume` assist cleanup. Use only after feature detection and never claim JavaScript keeps running while iOS suspends the host. Use `--htmlapp-text-scale` from the host for accessibility text scaling.
